## Task 1: compliance schema
- Ruling: restricted (and consent-withdrawn) faces must not be processed at all — add itap.match_face_suppressed(org, embedding, threshold) (best match among restricted/withdrawn identities ≥ threshold); recognition drops such faces (no detection, no new unknown identity); enrollment returns conflict `subject_restricted`; match_face contract unchanged. trigger_logs removed from org-scoped classes (platform purge cron stays). Legal hold targets of an active hold cannot be deleted (end the hold first). DSR erasure uses itap.restriction_context to unlink. Fold into T1 review fix round.
- Ruling (review fixes): #1 SQL guard on embedding/photo inserts refuses identities of restricted profiles (profile_processing_restricted, mapped); #2 BEFORE INSERT guard on detections refuses the insert with code subject_restricted (recognition already drops via match_face_suppressed, so this is a backstop); #3 hold helpers follow merges both ways. Segments: restricted subjects cannot be manually added and their open manual memberships are closed on restriction (rule rows close via evaluation); activity stats exclude restricted profiles; open sessions of a restricted identity are closed at restriction. Minors: restriction context save/restore; audit/auth_attempts retention floor 365 days; ended-hold targets don't block (Task 2 deletes ended-hold targets; document); covers_profile as UNION of indexed lookups; integrations update check allows status 'error' unchanged; integrations.secret encrypted like client keys (AES-GCM v2, AAD = integration id) — and excluded from event payloads.
- Ruling: hold timeline one-way (starts_at immutable once started; ends_at set once/shortened; no reactivation).
